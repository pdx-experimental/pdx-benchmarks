- Cell $a$: Both conditions pass ($+/+$).

- Cell $c$: Treatment fails, baseline passes ($-/+$, negative discordance).

### C.2 Forensic Step-Receipt Case Study: `v3_14_crypto_key_token_hash`
In task `v3_14_crypto_key_token_hash`, the objective requires three sequential steps:
1. `db_lookup` with key `api_credential_prod` $\to$ receipt: `{"client_id": "PDX_CLIENT_77", "salt_b64": "U0FMVF85OTAy"}`
2. `crypto_transform` with action `b64decode` and data `U0FMVF85OTAy` $\to$ receipt: `SALT_9902`
3. `crypto_transform` with action `sha256_prefix` and data `PDX_CLIENT_77:SALT_9902` $\to$ receipt: `d6023142`

Under Arm $C_{2s}$:
- Step 1: Dispatched `{"name": "tool_db_lookup", "args": {"key": "api_credential_prod"}}` $\to$ Success (`{"client_id": "PDX_CLIENT_77", "salt_b64": "U0FMVF85OTAy"}`).
- Step 2: Dispatched `{"name": "tool_crypto_transform", "args": {"op": "b64decode", "data": "U0FMVF85OTAy"}}` $\to$ Success (`SALT_9902`).
- Step 3: Dispatched `{"name": "tool_crypto_transform", "args": {"op": "sha256_prefix", "data": "PDX_CLIENT_77:SALT_9902"}}` $\to$ Success, computed gold receipt `d6023142`.
- Terminal Step (`step_final`): Model lacked an explicit stopping rule. Instead of executing `final_answer`, it re-invoked `crypto_transform` with the exact same arguments `{"op": "sha256_prefix", "data": "PDX_CLIENT_77:SALT_9902"}`, yielding an `empty_prediction` (no `final_answer`). Recorded as a failure.

Under Arm $C_{2sf}$:
- Steps 1–3 executed identically.
- Terminal Step: Governed by Rule 3 and Exemplar 4, the model recognized completion and emitted:
  ```json
  {"thought": "Calculations complete.", "action": "final_answer", "tool_call": null, "args": null, "artifact": "d6023142"}
  ```
The contract supplied an execution brake rather than inducing reasoning capacity.

## Appendix D: Governance Prompt Contracts & Exemplar Specifications

### D.1 System Prompt Rules
The governing system prompt enforces structured step execution:

```markdown
You are an isolated step execution agent.
You must respond ONLY with valid JSON conforming to the following schema:
{
  "thought": "one short sentence",
  "action": "execute_tool" | "final_answer",
  "tool_call": {"name": "<tool>", "args": {"key": "val"}},
  "answer": "<string>"
}

Available Tools:
<JSON Schema of available tools>

Rules:
1. Output ONLY the JSON object. No Markdown conversation, no preamble.
2. If action is 'execute_tool', 'tool_call' must specify a valid tool and non-empty args.
3. [Rule 3 Condition Dependent]
```

**Rule 3 Specification by Arm**:
- In Arm $C_{2sf}$: `"3. If action is 'final_answer', 'answer' must be ONLY the raw scalar value (number, identifier, or hash) with NO conversational filler, units, prefixes, or full sentences."`
- In Arms $C_0$ and $C_{2s}$: `"3. If action is 'final_answer', 'answer' must contain the final answer string."`

## Appendix E: Computational Infrastructure & Environment Invariants

All benchmarks were evaluated in isolated environments with fixed hardware specifications:
- **Compute Accelerators**: Dual NVIDIA Tesla T4 GPUs (16,384 MiB VRAM per GPU; aggregate 32,768 MiB).
- **Host Platform**: Linux 6.12.90+ x86_64, CUDA 12.8, PyTorch 2.10.0+cu128.
- **Quantization Engine**: BitsAndBytes INT8 (`load_in_8bit=True`, `llm_int8_threshold=6.0`), compute dtype `torch.float16`.
- **Generation Settings**: Greedy decoding (`temperature=0.0`, `do_sample=False`, `max_new_tokens=512`).
- **Tool Library**: Deterministic backend implementations (`src/tools.py`) adhering strictly to OpenAPI 3.0 schema declarations.
